# Перенос фото и «плашки» из сайта BLF в ПК-приложение

В этой папке лежит всё, что нужно, чтобы приложение на ПК показывало те же реальные фото
комплектующих, честные подписи и плашку «изображения нет» — без интернета и без CDN.

```
app-transfer/
├── deploy-to-app.sh        ← копирует файлы в приложение и сам подключает их в HTML
├── parts-photos.js         ← весь код фото (ключи, правила, partImg, плашка, onerror-фолбэк)
├── parts-photos.css        ← стили фото и плашки
├── blf-photos-bundle.js    ← то же самое ОДНИМ файлом: каталог + фото (если нет сборщика)
├── build-bundle.sh         ← пересобрать bundle после правок
├── data.js, catalog.js     ← каталог BLF (можно не копировать, если в приложении свой)
└── img/parts/*.jpg         ← 205 фото, 560×560, белый фон, ~6 МБ
```

## Быстрый путь (рекомендуется)

```bash
# 1. Забрать ветку с файлами
git fetch origin arena/0938f8d8-blf
git archive origin/arena/0938f8d8-blf app-transfer | tar -x

# 2. Скопировать всё в приложение и подключить в HTML
./app-transfer/deploy-to-app.sh /путь/к/приложению
```

Скрипт:

1. копирует `img/parts/*.jpg` (205 файлов), `parts-photos.js` и `parts-photos.css`;
2. вставляет `<link rel="stylesheet" href="parts-photos.css">` перед `</head>`;
3. вставляет `<script src="parts-photos.js"></script>` сразу после `data.js`
   (если `data.js` нет — перед `</body>` и предупредит об этом);
4. печатает проверку: сколько раз найдены стили и модуль в каждом HTML.

Ничего не перезаписывает, кроме своих же трёх файлов — можно запускать повторно.

## Что уже сделано в этой ветке для ПК-версии

Добавлена готовая десктопная оболочка `desktop/` (Electron): она открывает тот же
`index.html`, поэтому фото, каталог, конструктор и плашка работают как на сайте.

```bash
cd desktop
npm install
npm start            # запуск приложения
npm run dist:win     # BLF-Setup-1.0.0.exe + portable-версия (Windows)
npm run dist:linux   # AppImage
```

В установленную программу попадают ровно нужные файлы (222: 205 фото, 15 скриптов,
HTML и CSS) — без `node_modules`, `image-search` и мусора. Окно помнит размер и позицию,
внешние ссылки (DNS, Ozon, Rufus, дистрибутивы ОС) открываются в системном браузере.

## Если в приложении своя вёрстка карточек

Достаточно заменить вывод картинки на функции модуля:

```js
// было: <img src="..."> или иконка-эмодзи
// стало:
partImg(part, { size: 'md' })   // карточка каталога / слот конструктора
partImg(part, { size: 'sm' })   // миниатюра в полоске сборки
buildImgStrip(parts, 4)          // готовая полоска фото CPU+GPU+плата+RAM
photoBadge(part)                 // подпись «фото модели» / «типовое фото серии»
```

* `imgFor(part)` — путь к JPEG или `''`, если фото нет (пустой `src` не отдаётся никогда);
* `partImg(part)` — `<img>` с `alt`, `loading="lazy"` и `onerror`-фолбэком;
* нет фото (или файл не загрузился) → `partImg`, `imgFallback` и `onerror` рисуют плашку
  `.part-img-missing` с текстом «изображения нет» и названием позиции;
* фото ищутся в папке `PART_IMG_DIR` (по умолчанию `img/parts/`).

Модуль читает у объекта только `id`, `cat`, `name`, `brand` и `specs` — если в приложении
свой каталог, он тоже подойдёт; правила фото от этого не зависят.

## Если в приложении нет системы сборки

Подключите один файл вместо трёх:

```html
<link rel="stylesheet" href="parts-photos.css">
<script src="blf-photos-bundle.js"></script>
<script>
  const P = window.BLFPhotos;               // внутри уже лежит каталог + функции фото
  grid.innerHTML = P.COMPONENTS.slice(0, 60)
    .map(c => `<article class="card">${P.partImg(c, { size: 'lg' })}<h3>${c.name}</h3></article>`)
    .join('');
</script>
```

## Проверка после переноса

1. Откройте каталог комплектующих: у карточек должны быть фото, а не иконки.
2. У разных моделей — разные снимки (RTX 4090, RTX 3080, RTX 4060 выглядят по-разному).
3. Под фото — подпись «фото модели» или «типовое фото серии».
4. Временно переименуйте любой файл в `img/parts/` и обновите страницу — на его месте
   должна появиться плашка «изображения нет», а не пустое место и не «сломанная» иконка.
5. Откройте консоль: ошибок загрузки быть не должно.

## Что переносить не нужно

- `image-search/` — черновые кадры, из которых отбирались фото (в `.gitignore`);
- `node_modules/` (в т. ч. `desktop/node_modules`);
- тесты `/tmp/t*.js` — они проверяют сайт, а не приложение.
